Pyxis Pulls With No BCMA Record

🚨
Every Pyxis Remove for a selected drug, checked for a matching BCMA Device Dispense (same ADM_ID/Med ID, or same FIN/patient+day and Generic Name if ADM_ID doesn't line up). A pull with nothing here means medication left the cabinet with no administration ever charted for it — the classic diversion signal, and the reverse of every other check on this page (those all start from BCMA and ask "does Pyxis confirm this?"; this one starts from Pyxis and asks "did this ever reach a patient's chart?"). Needs both files loaded — a Pyxis pull can only be called unexplained once there's a BCMA record it could have matched against.

Pyxis Activity Summary — All Transaction Types

📋
Raw counts of every Pyxis transaction type seen, broken out by both drug name and Med ID — Remove, Return, Waste, Restock/Refill, Override, Discrepancy, Destock, whatever your facility logs — independent of any BCMA match. Med ID is shown separately since one generic drug can be stocked under more than one Med ID (different pockets/strengths); this is a movement tally, not a discrepancy check, so use it to spot overall drift (e.g. Removes far outpacing what's charted) before drilling into per-patient detail below. Internal Movement, Patient Transfer, and Override/Discrepancy/Unrecognized activity each have their own dedicated section further down.

Pyxis On-Hand Balance (from Beg/End)

🧮
Chains each pocket's Beg/End counts chronologically to get a current on-hand total per drug — not a computed guess, this is the actual pocket count Pyxis itself recorded before and after each transaction. Dose-based events like Waste (measured in MCG/MG/ML, not a pocket count) don't carry a Beg/End and are correctly excluded rather than mixed in. Pocket identity uses Med ID and Drw/Sub Drw/Pkt location together whenever both are available — the same Med ID can be stocked in more than one physical location at once, so location is needed to tell those apart; Med ID alone is used only when location is missing, and drug name alone (tagged unconfirmed pocket ID) only when both are missing. Empty return bin activity is excluded from this chain entirely — it tracks a separate return-bin compartment's own count, not the main dispensing pocket's, and would otherwise generate false gaps every time it's interleaved with real stock activity. Only available when the loaded Pyxis file includes Beg/End columns.

Pocket Balance Gaps

⚠️
For each pocket, one transaction's End should equal the next transaction's Beg. A break here means the pocket's count changed by something not in this report — a transaction before the report's date range, or a genuinely unexplained change worth investigating.

Other Flagged Pyxis Activity — Override / Discrepancy / Unrecognized

🚩
Includes explicit Override and Discrepancy transactions, plus any transaction type this tool doesn't otherwise recognize (e.g. Wrong item, Transfer to/from patient, My Items issue to/from patient — real Pyxis transaction types that simply haven't shown up in this facility's data before). An unrecognized type isn't automatically a problem — it may just be a legitimate workflow this tool hasn't been taught about yet — but it's surfaced here rather than silently absent, so it gets a look before being dismissed.

Internal Movement & Patient-to-Patient Transfers

↔️
Internal Movement (Destock, Reallocate) moves product between cabinets/locations without it ever reaching a patient — excluded from every reconciliation check above since there's no BCMA event that could confirm it. Patient Transfer (My Items transfer from/to user) re-attributes a med already pulled under one patient to a different patient (e.g. a surgery-cart scenario) rather than removing anything new from the cabinet — a BCMA gap that lines up with one of these transfers may have a benign explanation rather than being a real discrepancy, so check here before treating it as unaccounted for.
